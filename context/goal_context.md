# IROL Instruction 저장소 목표

## 1. 저장소의 목적

이 저장소는 IROL 팀의 **실험 PC 환경을 처음부터 구성하고 운용하기 위한 안내서**이다. 단순한 설치 명령 모음이 아니라, 기존 담당자가 가진 환경 구성 지식과 문제 해결 경험을 보존하여 다음 두 사용자가 활용할 수 있게 하는 것을 목표로 한다.

- Linux, ROS, 로봇 및 센서 환경을 처음 접하는 신규 인원
- 문서를 바탕으로 설치·점검·문제 해결을 보조하거나 자동화하는 AI agent

기존 기술 담당자가 없어도 신규 인원이 이 저장소를 학습 자료이자 실행 가능한 가이드로 사용하여 실험 환경을 구성할 수 있어야 한다. 장기적으로는 이 지식을 바탕으로 AI agent가 반복적인 설치, 상태 확인 및 문제 진단을 최대한 자동화할 수 있게 한다.

## 2. 현재 단계의 목표

현재 단계에서는 실제 PC를 새로 설치하거나 설치 절차를 검증하지 않는다. 현 담당자의 기억과 경험을 바탕으로 다음 내용을 빠짐없이 구조화하는 데 집중한다.

1. Ubuntu 설치부터 전체 실험 환경을 구성하는 순서
2. 각 하드웨어와 소프트웨어의 역할 및 의존 관계
3. 장비 연결, 드라이버·SDK 설치 및 환경 설정 방법
4. 센서 데이터를 ROS 2 토픽으로 수신하기 위한 절차
5. MoveIt, RTDE 등 사용 가능한 경로를 통한 UR 로봇 제어 절차
6. 설치와 운용 중 실제로 겪은 문제, 원인 판단 과정 및 해결 방법
7. 사람이 입력해야 하는 값과 그 값을 확인하는 방법
8. 추후 자동화할 수 있는 단계와 사람의 판단·물리 작업이 필요한 단계의 구분

담당자의 기억에 기반한 내용은 검증된 사실과 구분한다. 지금 확인할 수 없는 항목을 추측으로 확정하지 않고 `재검증 필요` 또는 이에 준하는 상태로 명시한다.

## 3. 대상 독자와 작성 수준

대상 독자는 관련 지식이 없는 신규 인원이다. 따라서 각 문서는 다음 원칙을 따른다.

- Linux, 셸, 네트워크, Python, ROS 2 용어를 처음 사용할 때 설명한다.
- 명령어만 제시하지 않고 명령의 목적, 실행 위치, 필요한 권한과 예상 결과를 설명한다.
- 작업 전에 필요한 하드웨어 연결과 선행 조건을 명시한다.
- 설정값을 그대로 제시하는 것에 그치지 않고 장비와 PC에서 값을 확인하는 방법을 설명한다.
- 정상 상태를 신규 인원이 스스로 판단할 수 있도록 확인 명령, 예상 출력 및 완료 기준을 제공한다.
- 실패 시 증상 → 확인 방법 → 가능한 원인 → 해결 방법 → 해결 확인 순서로 안내한다.
- AI agent가 단계와 조건을 해석할 수 있도록 모호한 표현을 피하고 명령, 입력, 출력 및 분기 조건을 구조적으로 기록한다.

## 4. 현재 문서화 범위

현재 범위는 **실험 PC 및 실험 PC에 직접 연결되거나 연동되는 장비**이다.

### 기준 실험 PC 환경

| 항목 | 기준 |
| --- | --- |
| 운영체제 | Ubuntu 22.04 |
| ROS | ROS 2 Humble |
| GPU | NVIDIA GeForce RTX 4090 |

CPU, 메인보드, 커널, NVIDIA 드라이버, CUDA 및 기타 세부 버전은 구성요소별 문서를 작성하면서 확인한다.

### 소프트웨어

- Ubuntu 22.04
- ROS 2 Humble
- MoveIt
- Python 및 Conda 환경
- UR 로봇 드라이버와 RTDE 등 로봇 제어 수단
- 각 센서 및 그리퍼에 필요한 드라이버·SDK·ROS 패키지

Conda는 Python 환경 충돌을 방지하기 위해 사용한다. ROS 2를 시스템 Python 환경에서 사용하는 방법과 Conda 환경에서 사용하는 방법의 차이, 적용 범위, 장단점 및 충돌 가능성을 구분하여 설명해야 한다.

### 로봇 및 주변 장치

- UR5 로봇과 컨트롤러
- Robotiq 2F-85 그리퍼
- OnRobot suction gripper
- Inspire Robots RH56E2
  - 아직 사용 경험이 없으며 현 담당자들이 개발·검증한 뒤 내용을 추가할 예정이다.

### 센서 및 추적 시스템

- LUCID Helios
- Intel RealSense D435
- Intel RealSense D455
- F/T 센서
  - 아직 사용 경험이 없으며 현 담당자들이 개발·검증한 뒤 내용을 추가할 예정이다.
- OptiTrack 및 이를 운용하는 Windows 실험 PC

각 장비의 정확한 연결 구조, 네트워크 설정 및 제어·수신 경로는 해당 구성요소를 정리할 때 확인한다.

## 5. 현재 범위에서 제외하는 내용

다음 항목도 전체 연구 환경에는 필요하지만 현재 문서화 범위에서는 제외한다.

- 개인 연구 컴퓨터의 설치와 개발 환경
- Isaac을 이용한 개인 PC 시뮬레이션
- Isaac 기반 강화학습 및 기타 학습 환경
- 별도로 관리되는 프로젝트 코드 저장소의 구현과 사용법
- 센서 데이터를 ROS 2 토픽으로 수신한 이후의 프로젝트별 처리·분석 방법

필요해지면 별도의 범위로 확장하되, 현재 실험 PC setup 문서와 섞지 않는다.

## 6. 완료 기준

이 저장소가 설명하는 setup의 기술적 완료 상태는 다음과 같다.

1. 실험 PC에 기준 운영체제와 필수 소프트웨어 환경이 구성되어 있다.
2. 대상 로봇, 그리퍼, 센서 및 OptiTrack 시스템이 인식되고 연결된다.
3. 각 대상 센서의 데이터를 ROS 2 토픽으로 수신할 수 있다.
4. UR 로봇을 MoveIt, RTDE 등 문서화 대상이 되는 제어 방법으로 제어할 수 있다.
5. 신규 인원이 각 단계의 성공 여부를 문서의 점검 절차로 판단할 수 있다.
6. 주요 실패 상황에 대해 원인을 좁히고 해결할 수 있는 트러블슈팅 절차가 있다.

현재는 실제 재설치 검증 단계가 아니므로, 위 완료 기준을 만족하는 절차를 우선 문서화하고 추후 검증 이력을 별도로 누적한다.

## 7. 문서에 포함해야 하는 공통 구조

구성요소별 문서는 최소한 다음 내용을 포함한다.

1. 구성요소의 역할과 전체 시스템 내 위치
2. 초보자를 위한 핵심 개념과 용어
3. 지원·사용 대상 모델 및 버전
4. 사전 준비와 물리적 연결
5. 설치 절차
6. 설정 절차와 설정값 확인 방법
7. 실행 및 사용 절차
8. ROS 2 인터페이스 또는 로봇 제어 인터페이스
9. 정상 동작 확인과 완료 기준
10. 트러블슈팅
11. 자동화 가능 범위와 수동 작업
12. 참고 자료, 정보 출처 및 검증 상태

전체 문서에서는 구성요소별 설명 외에도 설치 선후 관계, 네트워크 구성, 전체 시스템 시작·종료 순서 및 통합 점검 절차를 적절한 위치에 제공한다.

## 8. 트러블슈팅 작성 원칙

트러블슈팅은 해결 명령만 나열하지 않고 기존 담당자의 판단 지식을 전달해야 한다.

- 관찰되는 증상과 오류 메시지
- 문제가 발생한 단계와 환경
- 가장 먼저 확인할 항목
- 가능한 원인과 원인을 구분하는 방법
- 해결 절차
- 해결 후 정상화 확인 방법
- 데이터 손실, 설정 변경 또는 장비 동작과 관련된 주의사항
- 경험 기반인지 실제 재검증된 내용인지에 대한 상태

아직 사용하지 않은 장비는 임의의 해결법을 작성하지 않는다. 개발과 실제 사용 과정에서 확인된 내용을 이후에 추가한다.

## 9. AI agent 활용 방향

AI agent 자동화는 문서화 이후에 구성요소별로 검토한다. 현재부터 문서를 agent가 활용하기 쉬운 형태로 작성하되, 아직 자동화 범위나 실제 장비 제어 권한을 확정하지 않는다.

추후 각 절차를 다음과 같이 분류할 수 있어야 한다.

- agent가 안전하게 자동 실행할 수 있는 작업
- agent가 상태를 확인하고 사람에게 판단을 요청해야 하는 작업
- 관리자 권한이나 보안 정보가 필요한 작업
- 장비 연결·캘리브레이션 등 사람이 수행해야 하는 물리 작업
- 로봇의 실제 움직임처럼 별도의 안전 검토와 승인이 필요한 작업

비밀번호, 라이선스, 내부 주소 등 보안상 민감할 수 있는 정보는 저장소에 바로 기록하지 않는다. 필요한 경우 담당자에게 확인하고, 실제 값 대신 값의 확인 방법·입력 위치·안전한 보관 위치를 문서화한다.

## 10. 유지보수 방향

현재 지정된 유지보수 담당자는 없다. 향후 이 문서를 참고하여 프로젝트를 진행하는 인원이 다음 내용을 함께 갱신하는 것을 기본 방향으로 한다.

- 새로 확인한 버전과 호환성
- 실제 검증한 설치·실행 결과
- 새로 발생한 문제와 해결 과정
- 구성 변경에 따른 네트워크 및 실행 순서
- 신규 장비 또는 새로운 제어·수신 방법

문서가 기억에 의존하는 일회성 기록으로 끝나지 않도록, 각 항목에 작성·검증 상태를 남기고 후속 사용자가 경험을 이어서 축적할 수 있어야 한다.

## 11. 구성요소별 작성 시 확인할 사항

다음 내용은 목표 자체의 미확정 사항이 아니라, 각 구성요소 문서를 작성할 때 현 담당자에게 확인할 세부 정보이다.

- 정확한 장비 모델·세대·펌웨어 및 소프트웨어 버전
- PC와 장비의 물리적 연결 방식
- IP, 포트, 인터페이스 및 기타 네트워크 설정과 확인 방법
- 사용한 드라이버, SDK, ROS 2 패키지 및 설치 경로
- 실제 실행 명령과 필요한 설정 파일
- 발행·구독하는 ROS 2 토픽과 정상 메시지 확인 방법
- UR5의 MoveIt, RTDE 및 기타 실제 사용 제어 경로
- 장비별 시작·종료 순서와 안전 주의사항
- 실제로 겪은 오류, 시행착오 및 해결 경험
- 아직 기억나지 않거나 추후 실제 환경에서 재검증해야 하는 항목
